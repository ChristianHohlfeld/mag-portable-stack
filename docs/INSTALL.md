# Installing MAG on a fresh server

One entry point brings a blank Ubuntu 24.04 server to a running MAG:
packages, users, kernel settings, Tailscale, TLS and nginx, the audit layer,
the golden VM image, Gitea and its runner, the model runtime and the models,
speech, voices, Blender, the Idol worker with its weights, the room, both
bots with their VMs, and the backups. Fresh means without the data of a lost
host; to bring a host back *with* its data use
`ops/backup/system-restore.sh` (see [OPERATIONS.md](OPERATIONS.md)).

```bash
sudo apt-get install -y git
git clone https://github.com/ChristianHohlfeld/mag-portable-stack.git ~/mag-stack
cd ~/mag-stack
sudo ./install.sh
```

`./install.sh` runs the phases of `ops/install/run.sh` in order. Each phase
that went through is remembered in `/var/lib/mag-install`; when one stops
(a secret is missing, Tailscale waits for a login) it says what to do, and
running `sudo ./install.sh` again goes on there.

```bash
sudo ./install.sh --list           # phases and which are done
sudo ./install.sh --only PHASE     # one phase again
sudo ./install.sh --from PHASE     # that phase and all after it
```

Builds and downloads run on CPUs 28-55. The whole install takes hours, most of
it downloads: about 400 GB of models (mag-modeld fetches and checks them after
the `deploy` phase, in the background) and about 120 GB of Idol weights.

## What the server must have

- Ubuntu 24.04 (noble), x86_64, KVM (`/dev/kvm`).
- Two NUMA nodes and 56 logical CPUs: cores 0-13 run Lena, 14-27 Noah, 28-55
  everything else (`ops/models/models.json`). Other layouts need that file
  and the CPU sets adapted.
- Memory for both models (about 17 GB and 65 GB) plus the bot VMs and the 64
  GiB `magbot` keeps free (`ops/vm/config.json`).
- About 700 GB of free disk.
- Optional: an AMD MI50 (PCI id 1002:66a1) for photo to 3D, pictures and
  video. Its power cap stays at 72 W (`ops/idol/power-cap.sh` only lowers it).
- The owner account `chris` (the units name `/home/chris`) and the checkout
  in `/home/chris/mag-stack`.

## Secrets: what you put where

Nothing secret is in the repository. The `secrets` phase checks these and
creates what can be generated; templates are in `ops/install/templates`.

| File (root 0600 unless noted) | What | How |
|---|---|---|
| `/etc/default/mag-room` | `MAG_ROOM_VAPID_PUBLIC/PRIVATE` (web push), `MAG_ROOM_BRAVE_KEY` (web search) | generated by the installer (VAPID); the Brave key is optional, by hand |
| `/var/lib/magbot/room/access.json` (magbot 0640) | the owner's Tailscale login(s) | copy `templates/access.json`, fill in `owners` |
| `/etc/mag-acme/acme-dns.json` | the acme-dns accounts of `mag.stardenburg.de` and `bot.stardenburg.de` | `curl -X POST https://auth.acme-dns.io/register` once per name, store as in `templates/acme-dns.json`, CNAME `_acme-challenge.<name>` to its `fulldomain` |
| `/etc/credstore/tailscale.authkey` | optional: join the tailnet without a login link | a Tailscale auth key |
| `/etc/mag-stack/hf-token` | optional: Hugging Face token with access to `speridlabs/idol` | without it photo to 3D stays off |
| `/etc/mag-backup/system.env` | optional: `MAG_SYSTEM_REPO` (and `RESTIC_PASSWORD_FILE`) for the whole-system backup off the host | see `ops/backup/system.sh` |

Generated on the host and never needed by hand: Gitea's `app.ini` secrets,
the audit CA, the runner token, the Let's Encrypt keys, the bots' VM keys.

## The host's identity

MAG answers on the Tailscale address `100.123.114.16` with the names
`mag.stardenburg.de`, `*.bot.stardenburg.de` and `mag.tail3e02ae.ts.net`
(Gitea over Funnel). On a new server, in the Tailscale admin console: remove
the old node `mag`, name the new one `mag` and set its IPv4 to
`100.123.114.16`. DNS and certificates then stay as they are; the
`tailscale` phase stops with this hint until the address is right.

## The phases

| Phase | Does |
|---|---|
| `preflight` | Ubuntu 24.04, x86_64, the owner, KVM, NUMA layout, disk, MI50 |
| `packages` | `ops/install/packages.txt` with apt, `go` as a snap |
| `users` | user `magbot`, `/var/lib/magbot/room`, `/etc/magbot/config.json`, the owner into `libvirt`/`kvm` |
| `kernel` | `ops/boot/sysctl-mag.conf` (NUMA, map count) |
| `secrets` | the table above |
| `tailscale` | `ops/tailscale/install.sh`, then the address check |
| `trust` | ISRG roots, pinned restic and lego |
| `build` | CMake/Ninja build of everything in this repository |
| `libvirt` | the `default` NAT network, started with the host |
| `audit` | `ops/audit/install-audit.sh --apply` (gateway, web proxy, CA, firewall) and the Tailscale API exception |
| `golden` | `ops/vm/build-golden.sh` (pinned Ubuntu cloud image) |
| `tls` | nginx's base configuration, ACME renewal units, the room's certificate, the bots' wildcard |
| `gitea` | `ops/gitea/install.sh`, `ops/runners/install.sh` |
| `runtime` | `ops/models/build-runtime.sh` (pinned llama.cpp, CPU only) |
| `media` | speech recognizer, voices, Blender and its face landmarker (`ops/stt`, `ops/tts`, `ops/scene`) |
| `idol` | `ops/idol/env/setup.sh`: the ROCm venv from `requirements.lock`, idol-sdk at its commit with the MI50 patch, TripoSG, all weights (only with an MI50) |
| `deploy` | `ops/deploy.sh`: the release, nginx, the model supervisor (models download now), all services, timers, boot |
| `bots` | VMs `agent1` (Lena) and `agent2` (Noah) from the golden image |
| `funnel` | Gitea over Tailscale Funnel |
| `backup` | `ops/backup/install.sh`: nightly room/Gitea, the timers; VM saves and the weekly whole-system backup come with `deploy` |
| `check` | `ops/health.sh`, boot enablement, where to look next |

## What stays by hand

- The acme-dns registration and its CNAMEs (once per domain), the owner's
  login in `access.json`, the Tailscale address of the new node.
- Chris's phone daemon (`devices/s23`) is his own and not part of the install.
- The Brave key and the Hugging Face token, if wanted.
